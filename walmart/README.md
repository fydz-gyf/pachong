# Walmart HTTP Scraper V9

V9 keeps the proven Walmart `curl_cffi` + AdsPower dynamic-CDP path and changes Sorftime enrichment from per-page browser DOM scraping to direct HTTP.

## What changed in V9

- Walmart search data: still fetched by `curl_cffi` HTTP.
- Sorftime estimated monthly sales/revenue: now fetched from Sorftime by HTTP.
- AdsPower/SunBrowser is used at startup to read:
  - Walmart cookies / User-Agent;
  - the logged-in Sorftime extension token from `chrome.storage.local`.
- V9 reconstructs the same Sorftime payload generated by the installed extension:
  - `JsonData`: gzip + Base64;
  - `DataJson`: gzip + Base64;
  - endpoint: `ASINCombinationDetailsMake`.
- Sorftime's encrypted `{k,d}` response is decoded locally using the same DES-CBC + gzip logic as the installed extension.
- No browser page scrolling is required for normal Sorftime collection.
- Browser DOM mode is retained as an optional fallback.

## Sorftime fields

Excel keeps the two columns introduced in V8:

- `产品预计月销量（Sorftime）`
- `产品预计月销售额（Sorftime, USD）`

For Walmart, the extension's estimated monthly sales value maps to Sorftime `SaleCount`.
Estimated monthly revenue follows Sorftime's displayed rule:

`estimated monthly revenue = estimated monthly sales × current product price`

If Sorftime returns no estimate (`SaleCount <= 0`), V9 leaves both estimate cells blank rather than inventing a value.

## Normal use

1. Open the intended Walmart AdsPower profile.
2. Open a working `walmart.com` tab.
3. Make sure Sorftime is enabled and logged in in that same profile.
4. Double-click `start_walmart_scraper_v9.bat`.

The interactive startup asks for keywords, page count, image embedding, image concurrency, and whether to collect Sorftime estimates.

## Command-line example

```powershell
.\.venv\Scripts\python.exe run.py `
  -k "office chair" `
  -p 50 `
  --browser adspower `
  --sorftime-mode http
```

Disable Sorftime:

```powershell
.\.venv\Scripts\python.exe run.py -k "office chair" -p 10 --browser adspower --no-sorftime
```

Force the old browser-DOM mode for troubleshooting:

```powershell
.\.venv\Scripts\python.exe run.py -k "office chair" -p 1 --browser adspower --sorftime-mode browser
```

Disable automatic browser fallback if Sorftime HTTP fails:

```powershell
.\.venv\Scripts\python.exe run.py -k "office chair" -p 10 --browser adspower --no-sorftime-browser-fallback
```

## Existing checkpoints

Existing V7/V8 checkpoints are reusable. If a checkpoint contains Walmart product rows but no Sorftime metrics, V9 re-fetches the necessary Walmart search page through HTTP to reconstruct the Sorftime request and then fills the two estimate columns. It does not need to scroll the Walmart page in AdsPower unless HTTP Sorftime fails and browser fallback is enabled.

## Browser requirement

For normal V9 Sorftime HTTP operation, AdsPower is needed at startup to supply the logged-in Sorftime token. After that, Sorftime calls are HTTP-direct. Keeping AdsPower open is still recommended because the Walmart scraper can use the visible browser as a manual-verification fallback if Walmart challenges standalone HTTP traffic.

The scraper does not solve or bypass Walmart human-verification pages.
